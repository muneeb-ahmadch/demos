How I'd build yours

This page is the first slice. Here is how it becomes the repository, test suite and README you asked for.

1

Backend that can't double-book

Node + TypeScript on Fastify, your four endpoints. In Postgres the database itself refuses overlapping bookings (an exclusion constraint), so it holds even with several API servers running. A clash comes back as a 409 carrying the booking it hit.

2

React front end

Rooms list, day view and booking form with client-side validation, as above. A late conflict refreshes the day and offers the next free slot instead of showing an error. Hooks and context only, with loading and error states on every call.

What guarantees it in the real build (Postgres). In this browser demo there is no database, so a per-room lock stands in for it:

-- the database refuses overlaps itself, whatever the app servers do
CREATE EXTENSION IF NOT EXISTS btree_gist;
ALTER TABLE bookings ADD CONSTRAINT bookings_no_overlap
  EXCLUDE USING gist (room_id WITH =, tstzrange(start_time, end_time, '[)') WITH &&);
-- '[)' is half-open: a 10:00 end and a 10:00 start do not collide (your back-to-back rule)
-- the API maps SQLSTATE 23P01 (exclusion_violation) to 409 + the conflicting booking

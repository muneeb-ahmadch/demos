4 · The real build

How I'd build yours

This page is the first slice. Here is how it becomes your three milestones.

1

Scorer audit (40%)

Read your scoring code and answer keys, run canaries like these against it (wrong answers, near-misses, formatting and Unicode tricks, blank or malformed keys), and report every case where it passes something it should fail, each with the failing input.

2

Blind test set (40%)

Write 20 synthetic business records and about 30 questions with a frozen answer key: current values, superseded values, "as of" dates and no-answer questions. Delivered to you only, never to the developer.

3

Answer-filter review and call (20%)

Review the code that decides which facts answer a question, list false matches, missed matches and fragile word matching, and walk you through it on a one-hour Upwork call.

For your developer: the canary run and both scorers

The same canaries, run through both scorers in your browser. The typical scorer lowercases, strips punctuation and checks the key is a substring of the answer. The stricter one normalises Unicode (NFKC), parses amounts and dates as typed values, requires exactly one value, rejects hedges and superseded values, and treats a blank key as an error. It was written against these canaries, so its clean score is not a claim about anything else; the point is the typical scorer's misses.
